# 渲染帧的数据与资源边界

渲染器必须同时满足三个约束：游戏线程准备的数据在录制期间保持稳定；时序算法只能引用已被 GPU 提交接受的帧；物理资源必须保活到最后一次 GPU 使用结束。这三个边界不相同，不能用一个“本帧完成”状态代替。

## 帧输入与反馈

`RasterFramePacket` 持有场景更新、相机和配置快照。需要场景变化信息的 pass 显式接收 `SceneUpdateBatch`，曝光适应显式接收帧时间。`RasterContext` 保留设备、场景及长期渲染资源，不再临时挂接指向某一帧的场景指针。

录制参数在图编译、录制期间固定。图的 setup 工作在返回前汇合，因此这些步骤可以引用当前 packet；交给 GPU 的命令持有其需要的资源，不依赖 packet 继续存在。

`RasterConfig` 表达用户输入，`RasterFrameStatus` 表达渲染反馈。反馈的 optional 状态区分“本帧没有运行管线”和“运行过，计数为零”。剔除统计仍来自最近完成的 GPU 回读，其采样帧不保证等于携带它的反馈帧。Cooperative Ops 的累计次数归渲染 pass 所有，不再通过滞后的 UI 配置来回传递。

RT 调试输入与反馈保存在编辑器配置的调试状态中。渲染器消费输入快照、返回 profiler 和纹理名称；ImGui 控件由编辑器绘制。渲染提交仍负责 UI 绘制数据的上传与合成，这是实际 GPU 工作需要的责任。

## AO 历史的唯一推进点

`AoPass` 每帧生成一个 `AoFrameResources`，统一选择全分辨率或半分辨率资源、当前写槽和历史槽。图声明、shader 参数、AO 合成和 TensorRT 使用同一个选择结果。

每个分辨率保留一对最终 AO、对应的几何历史，以及一张降噪前的 AO。启用时序降噪时，求值写入噪声图，降噪直接写入当前最终槽；其他模式直接求值到最终槽。这样不再需要独立的累积双缓冲和回拷 pass。TensorRT 继续缓存物理身份稳定的最终双缓冲，按写槽索引选择当前帧。

`WaitSubmitted` 确认原生提交被接受后，才提交 AO/AA 的历史索引和相机状态。拒绝提交不会推进历史；CUDA 前缀已提交也不能独自确认整帧历史。首次使用、资源重建或分辨率切换会禁用旧历史；TensorRT 的上一帧 AO 在无有效历史时使用当前 AO。TensorRT 网络自身的递归 embedding 仍属于其独立的推理状态，不由 AO 历史标志管理。

这保证了历史引用的有效性，并不代表 GPU 已执行完成。跨帧执行顺序和资源保活仍由既有队列提交、同步和完成机制负责。

## 临时资源与 GPU 完成

亮度直方图只在当前图中使用，PNG 导出的图像快照只服务一次复制与回读。它们由图创建临时资源；跨帧的曝光值仍由 Tonemapping pass 持有。

合并录制路径在 lowering 前使用现有 transient allocator 分配物理资源。录制期间图提供物理绑定；命令流继承 lowering 的资源所有权，随后沿提交和 GPU 完成路径保活。录制结束即可清除图绑定，但资源池只有在在途持有者释放后才能复用资源。没有增加独立的回收计时或完成状态。

分配、lowering、录制或命令合并失败时，作用域清理释放临时绑定。录制和组装先在私有命令流中进行，成功后才追加到调用方命令列表。多队列同步继续由原来的 active recording 路径处理。

## 阴影计算的单位

方向光与点光共享采样算法，但不共享投影尺度：方向光使用正交范围、NDC 深度和光源角度；点光使用光源半径、近远平面，以及当前 cubemap 面的轴向深度。

两种上下文分别表达这些量，PCF/PCSS 复用真正相同的采样流程。特别地，点光的 `receiverFaceDepthWorld` 是面轴深度，不是到光源的径向距离。这次整理保持既有采样数量、循环属性、数值公式和 CPU/HLSL 上传布局。
